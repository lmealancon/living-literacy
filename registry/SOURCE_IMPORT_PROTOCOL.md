# Source-to-canonical skill import protocol

1. Locate the full original 91 candidate definitions, identifiers and dependency edges from the earlier design artifacts. A count summary is not sufficient.
2. Preserve original wording and identifiers in a read-only source snapshot; log provenance and author/reviewer.
3. Compare actual inventory against `DOMAIN_MANIFEST.json`. The listed counts are provisional and do not establish that IDs are contiguous.
4. Complete `ADJUDICATION_WORKSHEET.csv`; resolve four issues with documented task examples and instructional consequences.
5. Decide whether to retain 91 meaningful skills or extend toward 150+ using expert-defined distinct skills; never fabricate padding.
6. Import to `SKILL_REGISTRY.json` as draft, with version and review metadata; validate schema, duplicate IDs, dependency targets and graph cycles.
7. Obtain educational approval before publishing. Approval for prototype does not authorize diagnosis, mastery or production.
8. Maintain migration mapping for changed identifiers and immutable published versions.

## Explicit missing source
The v0.1 package contains aggregate counts and issue IDs, not the original 91 full definitions. This package intentionally does not reconstruct them from memory or guesswork.
